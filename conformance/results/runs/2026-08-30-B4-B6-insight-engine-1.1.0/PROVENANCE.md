# Provenance of DELIVERABLE-transcribed.md

Kept beside the file, not inside it. The first attempt put this note at the head of the
deliverable and the conformance checker failed it: F2 requires the compliance receipt on the
**first line**, and a provenance comment had pushed it down. The checker was right twice over —
the rule held, and a transcription carrying the transcriber's commentary inside it is not a
faithful transcription. The note moved; the file did not change.

PROVENANCE, READ BEFORE RELYING ON THIS FILE.

This is a TRANSCRIPTION, not the artefact. The run wrote its deliverable to
  ...\local-agent-mode-sessions\...\local_0709a6b9-...\outputs\block-remediation-analysis-2026-08-30.md
which is a temporary session folder. By the time the scoring session tried to copy it, the folder had
been cleared: a recursive search of the whole Claude application directory for "block-remediation*"
returned nothing.

What follows was therefore transcribed verbatim from the run output as pasted into the scoring
session on 2026-08-30. It is a copy of a copy. Its fidelity rests on that paste, not on the file the
engine wrote, and two losses are known rather than suspected:

  1. Whatever the paste itself dropped or reflowed is dropped or reflowed here too.
  2. The conversational narration that surrounded the document in the run - the triage line, the gate
     exchanges as they happened, the adjudication commentary - is NOT reproduced. Only the document
     that followed the separator is. The narration survives only in the session transcript.

Nothing has been summarised, corrected or improved. Where the text reads oddly, it read oddly in the
run.

This corpus copies fixed texts byte-for-byte and never retypes them, because retyping produced the
v0.1.20 legend defect. That rule could not be followed here: there was nothing left to copy from.
Transcription was chosen over losing the evidence entirely, and this note is the cost of that choice
being visible rather than silent.
